# NOOPI (누피) Service Specification

## 서비스 정보

-   서비스명: **NOOPI**
-   한글명: **누피**
-   서비스 유형: 여럿이 같은 공간에서 함께 즐기는 실시간 멀티플레이 게임
    웹서비스
-   핵심 문구: **게임은 사람끼리, 진행은 웹이.**
-   한 줄 정의: **여럿이 모였을 때 QR 하나로 바로 시작하는 실시간 게임
    플랫폼.**

## 1. 목적

여러 명이 한 공간에 모였을 때 별도의 앱 설치나 회원가입 없이 각자의
스마트폰으로 접속하여 함께 게임을 진행할 수 있는 모바일 웹 기반 실시간
게임 플랫폼이다.

실제 대화와 행동은 참가자들이 직접 진행한다. 서비스는 게임 진행에 필요한
정보와 상태를 관리한다.

## 2. 핵심 원칙

-   별도 앱 설치 없이 모바일 웹에서 이용한다.
-   MVP에서는 회원가입과 로그인을 요구하지 않는다.
-   QR 또는 Room Code를 이용해 빠르게 참가할 수 있어야 한다.
-   참가자 간 대화와 행동은 실제 공간에서 이루어진다.
-   서비스는 역할 전달, 순서 결정, 투표, 결과 집계 등 진행에 필요한
    기능만 담당한다.
-   Player가 현재 수행할 수 있는 행동만 제공한다.
-   게임 진행 상태의 최종 기준은 서버다.
-   한 게임이 종료되어도 Room과 Player는 유지한다.

## 3. 핵심 개념

### Client

서비스에 접속한 브라우저 단위의 익명 사용자다.

### Room

함께 게임을 플레이하는 사람들이 모여 있는 공간이다. 특정 게임에 종속되지
않는다.

### Player

Client가 특정 Room에 참가한 상태다.

Player는 다음과 같은 Room 단위 정보를 가진다.

-   닉네임
-   성별
-   방장 여부
-   참가 상태
-   연결 상태

닉네임과 성별은 Client의 전역 프로필이 아니라 해당 Room의 Player 정보로
관리한다.

### GameSession

Room에서 진행되는 게임 한 판이다. 게임을 새로 시작할 때마다 새로운
GameSession을 생성한다.

## 4. Client 식별

MVP에서는 계정 대신 익명 `clientId`를 사용한다.

서비스 최초 접속 시 충분히 충돌 가능성이 낮은 랜덤 식별값을 생성하고,
동일 브라우저에서 다시 접속하면 기존 값을 사용한다.

사용 목적: - 동일 브라우저 식별 - 동일 Room 중복 참가 방지 - 새로고침 후
Player 복구 - 일시적인 연결 종료 후 재접속 - 중복 행동 방지 보조

`clientId`는 인증 수단이 아니다. 브라우저 데이터가 삭제되거나 다른
브라우저/기기를 사용하면 새로운 Client로 취급될 수 있다.

## 5. Room

Room은 참가자들이 모여 있는 공간이다. 하나의 Room에서 여러 GameSession을
순차적으로 진행할 수 있다.

Room에는 사람이 직접 입력할 수 있는 짧은 Room Code를 제공하며 QR을
이용한 참가도 지원한다.

## 6. Player

Client가 Room에 참가하면 해당 Room의 Player가 된다.

Player는 닉네임, 성별, 방장 여부, 참가 상태, 연결 상태를 가진다.

동일 Client는 동일 Room에서 하나의 Player로만 존재한다.

닉네임과 성별은 Room 단위 Player 정보다.

따라서 동일 Client라도 다른 Room에서는 다른 닉네임과 성별을 선택할 수
있다.

하나의 Room에서는 동일 닉네임을 중복 사용할 수 없다.

닉네임은 공백을 제외한 1글자 이상 5글자 이하여야 한다.

### 성별

Room 생성 또는 참가 시 Player는 성별을 선택한다.

MVP에서 지원하는 값은 다음과 같다.

-   `MALE`
-   `FEMALE`

성별은 향후 게임 규칙 또는 Player 표현에서 활용할 수 있다.

## 7. 방장

Room을 생성한 Player가 최초 방장이 된다.

방장은 게임 선택, 게임 설정, 게임 시작, 게임별 방장 행동, 다음 게임
선택, 게임 종료, Room 종료 권한을 가진다.

방장의 연결이 종료되어도 Room을 자동 종료하거나 방장 권한을 이전하지
않는다. 참가자는 제한 없이 재접속을 기다리거나 화면의 나가기 행동으로
직접 Room을 떠날 수 있다. 방장이 명시적으로 나가면 Room을 종료하고 남은
참가자를 모두 홈 화면으로 이동시킨다.

방장이 영구적으로 이탈한 경우 다른 Player에게 방장 권한을 이전할 수
있어야 한다.

## 8. 기본 이용 흐름

Room 생성:
`서비스 접속 → 닉네임 및 성별 선택 → Room 생성 → QR/Room Code 공유 → 참가자 대기 → 게임 선택 → 게임 시작`

Room 참가:
`QR 또는 Room Code 입력 → 닉네임 및 성별 선택 → Room 참가 → 게임 시작 대기`

게임 종료: `게임 종료 → 같은 게임 다시하기 / 다른 게임 선택 / Room 종료`

## 9. 재접속

새로고침이나 일시적인 네트워크 연결 종료로 기존 Player가 중복
생성되어서는 안 된다.

동일 Client가 기존 Room에 다시 접근하면 기존 Player를 찾아 현재 상태를
복구한다.

복구 대상에는 Room, Player의 닉네임과 성별, 현재 GameSession, 현재 게임
단계, 해당 Player에게 공개된 정보, 이미 수행한 행동 등이 포함될 수 있다.

## 10. MVP 범위

-   모바일 웹
-   익명 Client 식별
-   Room 생성
-   QR 초대
-   Room Code 참가
-   닉네임 및 성별 선택
-   Player 관리
-   방장
-   게임 선택
-   GameSession
-   실시간 상태 동기화
-   새로고침 및 재접속
-   같은 게임 다시하기
-   다른 게임 선택
-   Room 나가기 및 종료
-   지원 게임: 라이어 게임, 블라인드 게임

## 11. MVP 제외 범위

-   회원가입
-   로그인
-   친구
-   채팅
-   음성 채팅
-   상세 프로필
-   랭킹
-   전적
-   아이템
-   복잡한 점수 시스템

## 12. 최종 원칙

Room은 **사람들이 모여 있는 공간**이다.

GameSession은 **그 Room에서 진행되는 게임 한 판**이다.

각 게임은 **자신의 규칙과 상태를 독립적으로 가진다.**

서비스 공통 영역이 특정 게임의 규칙에 종속되지 않도록 한다.
