# NOOPI (누피) Liar Game Specification

## 1. 게임 개요

참가자 중 정확히 한 명이 라이어로 선정되고 나머지는 모두 시민이다.

시민들은 동일한 제시어를 알고 있지만 라이어는 제시어를 알지 못한다.

참가자들은 실제 현장에서 서로 대화하면서 라이어를 추리한다.

서비스는 카테고리 제공, 제시어 선정, 역할 선정/전달, 첫 발언자 선정,
투표, 결과 집계, 동률 처리, 라이어 판정, 마지막 제시어 추측, 승패 판정을
담당한다.

## 2. 참가 인원

-   최소: **3명**
-   권장: **4\~8명**
-   최대: **12명**

3명 미만 또는 12명을 초과하면 게임을 시작할 수 없다.

## 3. 라이어

참가 인원과 관계없이 라이어는 항상 **1명**이다.

나머지는 모두 시민이다. 라이어 수 설정 기능은 제공하지 않는다.

## 4. 카테고리

방장은 게임 시작 전에 제시어 카테고리를 선택한다.

카테고리 목록은 클라이언트에 하드코딩하지 않는다.

클라이언트는 서버로부터 현재 사용 가능한 카테고리 목록을 조회하여
표시한다.

따라서 카테고리 추가/비활성화가 클라이언트 재배포 없이 반영될 수 있어야
한다.

카테고리에는 식별값, 코드, 표시 이름 등이 포함될 수 있으며 구체적인 API
구조는 `API_SPEC.md`에서 정의한다.

## 5. RANDOM 옵션

`RANDOM`은 실제 제시어 그룹을 의미하는 저장 카테고리가 아니라 전체 활성
제시어를 대상으로 하는 선택 옵션이다.

클라이언트가 자체적으로 `RANDOM`을 만들어내지 않는다.

서버가 제공하는 카테고리 선택 목록에 `RANDOM` 옵션을 포함한다.

`RANDOM` 선택 시 서버는 전체 활성 제시어를 대상으로 제시어를 선정한다.

## 6. 제시어 관리

제시어는 서버에서 관리한다.

클라이언트는 전체 제시어 목록을 조회하거나 보유하지 않는다.

각 제시어는 하나의 실제 카테고리에 속하며 서버는 활성 상태인 제시어만
게임에서 사용할 수 있다.

## 7. 제시어 선정

일반 카테고리가 선택되면 서버는 해당 카테고리의 활성 제시어 중 하나를
선정한다.

`RANDOM`이면 전체 활성 제시어 중 하나를 선정한다.

같은 Room에서 최근 사용한 제시어는 가능한 한 반복하지 않는다.

제시어 선정은 서버에서만 수행한다.

## 8. 게임 시작 조건

-   GameSession 참가자가 3\~12명
-   게임 진행에 필요한 Player가 정상적으로 참가 중
-   유효한 카테고리가 선택됨
-   선택 가능한 활성 제시어가 존재함

최종 시작 가능 여부는 서버에서 판단한다.

## 9. 역할 선정

게임 시작 시 GameSession 참가자 중 정확히 한 명을 서버가 랜덤으로
라이어로 선정한다.

나머지는 시민이다.

역할은 GameSession마다 새롭게 선정하며 이전 게임의 역할은 다음 게임에
영향을 주지 않는다.

## 10. 역할 및 제시어 공개

서버는 현재 Player에게 허용된 정보만 제공한다.

시민: - 역할 `CITIZEN` - 현재 게임의 제시어

라이어: - 역할 `LIAR` - 제시어는 제공하지 않음

전체 역할 또는 제시어를 모든 클라이언트에 전달한 뒤 UI에서 숨기는 방식은
사용하지 않는다.

## 11. 역할 확인

각 Player는 자신의 역할을 확인한다.

모든 GameSession 참가자가 역할 확인을 완료하면 다음 단계로 진행한다.

역할 확인 여부는 서버에서 관리한다.

## 12. 첫 발언자

모든 참가자의 역할 확인이 완료되면 서버가 참가자 중 한 명을 랜덤으로 첫
발언자로 선정한다.

시민과 라이어 모두 선정 대상이며 첫 발언자는 전체 참가자에게 공개한다.

## 13. 토론

첫 발언자 선정 이후 실제 대화는 참가자들이 직접 진행한다.

서비스는 발언 내용, 발언 횟수, 발언 시간, 전체 발언 순서를 관리하지
않는다.

## 14. 투표 시작

MVP에서는 방장이 투표 시작을 요청한다.

서버는 방장 권한과 현재 게임 상태를 검증한 후 투표를 시작한다.

## 15. 투표

모든 활성 게임 참가자가 투표한다.

각 Player는 라이어라고 생각하는 참가자 한 명을 선택한다.

-   자기 자신에게 투표할 수 없다.
-   한 번 제출한 투표는 변경할 수 없다.
-   하나의 투표 라운드에서 한 번만 투표할 수 있다.
-   중복 투표 여부는 서버에서 검증한다.

## 16. 투표 진행 정보

투표 진행 중 공개: - 전체 투표 인원 - 투표 완료 인원 - 각 Player의 투표
완료 여부

투표 진행 중 비공개: - 각 Player의 투표 대상 - 현재 득표수 - 현재 최다
득표자

## 17. 투표 종료

모든 투표 대상 Player가 투표를 완료하면 서버가 자동으로 해당 투표
라운드를 종료한다.

## 18. 투표 결과

투표 종료 후 다음 정보를 전체 참가자에게 공개한다.

-   각 Player가 누구에게 투표했는지
-   참가자별 총 득표수
-   최다 득표자

최다 득표자가 한 명이면 해당 Player를 최종 지목자로 결정한다.

## 19. 동률 및 재투표

최다 득표자가 여러 명이면 동률 후보만 대상으로 재투표한다.

모든 활성 게임 참가자가 다시 투표하며 자기 자신에게 투표할 수 없다.

재투표 횟수에는 제한을 두지 않는다.

재투표에서도 최다 득표자가 여러 명이면 해당 라운드의 동률 후보만
대상으로 다시 재투표한다.

단독 최다 득표자가 결정될 때까지 재투표를 반복한다.

서버가 동률 후보 중 한 명을 임의 또는 랜덤으로 최종 지목자로 선정하지
않는다.

`최초 투표 → 동률 → 동률 후보 재투표 → 다시 동률이면 재투표 반복 → 단독 최다 득표자 결정`

## 20. 최종 지목

최종 지목자가 결정되면 서버가 해당 Player의 실제 역할을 확인한다.

### 시민을 지목한 경우

라이어 검거 실패다.

즉시 라이어 승리로 게임을 종료하고 실제 라이어를 전체 참가자에게
공개한다.

이 경우 라이어의 제시어 추측은 진행하지 않는다.

### 라이어를 지목한 경우

라이어 검거 성공이다.

즉시 시민 승리로 처리하지 않고 라이어에게 마지막 제시어 추측 기회를
제공한다.

## 21. 라이어의 마지막 추측

라이어는 제시어를 한 번 추측할 수 있다.

입력 및 제출 행동은 라이어에게만 허용한다.

시민은 별도 행동 없이 제출을 기다린다.

한 번 제출한 답은 변경할 수 없다.

## 22. 정답 판정

정답 판정은 서버에서 수행한다.

클라이언트는 정답 여부를 직접 판단하지 않는다.

기본 정규화: - 앞뒤 공백 제거 - 대소문자 차이 무시 - 불필요한 연속 공백
정리

필요한 경우 서버에서 허용 정답을 관리할 수 있다.

MVP에서는 LLM 기반 의미 판정을 사용하지 않는다.

## 23. 승리 조건

시민 승리: 1. 실제 라이어를 최종 지목 2. 라이어가 마지막 제시어 추측
실패

라이어 승리: 1. 최종 지목자가 시민 2. 검거된 라이어가 마지막 제시어 추측
성공

## 24. 게임 상태

-   `READY`
-   `ROLE_REVEAL`
-   `DISCUSSION`
-   `VOTING`
-   `VOTE_RESULT`
-   `REVOTING`
-   `LIAR_REVEAL`
-   `LIAR_GUESS`
-   `FINISHED`
-   `CANCELLED`

서버는 현재 게임 상태에서 허용되는 행동만 처리한다.

## 25. 연결 종료 및 재접속

Player의 연결이 일시적으로 종료됐다는 이유만으로 즉시 게임에서 제외하지
않는다.

공통 연결 및 재접속 정책은 `REALTIME_SPEC.md`를 따른다.

재접속 시 역할, 시민의 제시어, 역할 확인 여부, 현재 게임 단계, 기존 투표
여부, 라이어 추측 제출 여부 등을 복구한다.

재접속으로 인해 이미 수행한 행동을 다시 수행할 수 있어서는 안 된다.

## 26. 투표 중 연결 종료

투표 중 연결이 종료되면 일정 시간 동안 재접속을 기다린다.

장시간 복귀하지 않는 경우 방장은 해당 Player를 현재 GameSession에서
제외할 수 있다.

제외된 Player가 이미 제출한 투표가 있다면 무효 처리하고 필요한 투표
인원을 다시 계산한다.

## 27. 라이어 이탈

라이어의 연결이 일시적으로 종료된 경우 재접속을 기다린다.

라이어가 명시적으로 Room을 나가거나 장시간 복귀하지 않으면 현재
GameSession을 취소한다.

게임 중간에 새로운 라이어를 선정하지 않는다.

## 28. 다시하기

같은 라이어 게임을 다시 시작하면 새로운 GameSession을 생성한다.

라이어, 제시어, 첫 발언자를 새롭게 선정하며 기존 Player와 닉네임은
유지한다.
