# NOOPI (누피) Liar Game Specification

## 1. 문서 목적

이 문서는 NOOPI의 라이어 게임 규칙과 상태 전이를 정의한다.

Frontend와 Backend는 이 문서를 라이어 게임 규칙의 Source of Truth로
사용한다.

------------------------------------------------------------------------

## 2. 핵심 원칙

-   라이어는 항상 정확히 1명이다.
-   실제 대화와 추리는 참가자들이 오프라인에서 진행한다.
-   웹은 역할 확인, 진행 상태, 투표, 결과 판정 등을 보조한다.
-   서버가 게임 상태와 결과의 Source of Truth다.
-   Frontend는 역할 배정, 투표 집계, 동률 판정, 승패 판정을 직접
    수행하지 않는다.
-   현재 Player가 수행할 수 있는 행동만 제공한다.

------------------------------------------------------------------------

## 3. 참가 인원

-   최소: 3명
-   권장: 4\~8명
-   MVP 최대: 12명
-   라이어: 항상 1명
-   시민: 참가자 수 - 1명

라이어 수를 설정하는 기능은 제공하지 않는다.

------------------------------------------------------------------------

## 4. 카테고리와 제시어

카테고리와 제시어는 Backend에서 관리한다.

Frontend에 실제 카테고리 목록이나 전체 제시어 목록을 하드코딩하지
않는다.

`RANDOM`은 실제 저장 카테고리가 아니라 서버가 제공하는 가상 선택
옵션이다.

`RANDOM` 선택 시 서버가 모든 활성 제시어 중 하나를 선택한다.

가능하면 같은 Room에서 최근 사용한 제시어의 반복을 피한다.

전체 제시어 목록을 Client에 전달하지 않는다.

------------------------------------------------------------------------

## 5. 역할 배정

게임 시작 시 서버가 현재 GameSession 참가자 중 정확히 1명을 무작위로
라이어로 선정한다.

나머지는 모두 시민이다.

새 GameSession마다 역할을 다시 선정한다.

이전 판의 라이어 여부는 다음 판의 선정 확률에 영향을 주지 않는다.

------------------------------------------------------------------------

## 6. 비밀 정보

### 시민

시민은 다음 정보를 확인한다.

-   자신의 역할: `CITIZEN`
-   제시어

### 라이어

라이어는 다음 정보만 확인한다.

-   자신의 역할: `LIAR`

라이어에게 제시어를 전달하거나 표시하지 않는다.

게임 종료 전 다른 Player의 역할을 공개하지 않는다.

서버는 모든 역할과 제시어를 모든 Client에 내려준 뒤 UI에서 숨기는
방식으로 구현하지 않는다.

------------------------------------------------------------------------

## 7. 역할 확인

각 Player는 자신의 역할을 확인한 후 확인 행동을 제출한다.

서버는 Player별 `roleChecked` 상태를 관리한다.

모든 활성 참가자가 역할 확인을 완료하면 다음 단계로 진행한다.

이미 확인한 Player는 다시 확인할 수 없다.

------------------------------------------------------------------------

## 8. 첫 발언자

모든 Player의 역할 확인이 완료되면 서버가 참가자 중 한 명을 첫 발언자로
무작위 선정한다.

첫 발언자는 시민 또는 라이어 모두 가능하다.

첫 발언자 정보는 전체 참가자에게 공개한다.

------------------------------------------------------------------------

## 9. 추리 단계

첫 발언자부터 참가자들이 실제 공간에서 차례로 제시어에 관해 이야기한다.

웹은 발언 내용을 기록하거나 관리하지 않는다.

추리 단계에서는 불필요한 화면 상호작용을 최소화한다.

충분히 이야기했다고 판단하면 방장이 투표를 시작한다.

------------------------------------------------------------------------

## 10. 투표 시작

투표 시작은 방장만 요청할 수 있다.

서버가 현재 게임 상태에서 투표 시작이 가능한지 검증한다.

투표가 시작되면 모든 활성 참가자가 한 표씩 행사한다.

------------------------------------------------------------------------

## 11. 투표 기본 규칙

-   모든 활성 참가자가 투표한다.
-   자기 자신에게 투표할 수 없다.
-   한 Player는 한 투표 라운드에 한 번만 투표할 수 있다.
-   제출한 투표는 변경할 수 없다.
-   서버가 현재 `voteRound`를 검증한다.
-   서버가 현재 Player에게 유효한 후보인지 검증한다.
-   투표는 비밀투표다.

논리적 유일성:

``` text
gameSessionId + voteRound + voterPlayerId
```

------------------------------------------------------------------------

## 12. 투표 비밀 보장

**누가 누구에게 투표했는지는 항상 비공개다.**

다음 모든 시점에 개인별 투표 대상을 공개하지 않는다.

-   투표 진행 중
-   해당 투표 라운드 종료 후
-   재투표 중
-   게임 종료 후

Client에 다음과 같은 정보를 제공하거나 표시하지 않는다.

``` text
종윤 → 철수
예은 → 종윤
```

`PLAYER_VOTED` 실시간 이벤트에도 `targetPlayerId`를 포함하지 않는다.

`GET /state` 역시 다른 Player의 투표 대상을 반환하지 않는다.

------------------------------------------------------------------------

## 13. 투표 진행 중 공개 가능한 정보

투표 진행 중에는 다음 정보만 공개할 수 있다.

-   전체 투표 필요 인원
-   현재 투표 완료 인원
-   각 Player의 투표 완료 여부
-   현재 Player 자신의 투표 제출 여부
-   현재 Player가 선택할 수 있는 후보

다음 정보는 공개하지 않는다.

-   다른 Player의 투표 대상
-   현재 후보별 득표수
-   현재 1위 후보
-   실시간 순위

------------------------------------------------------------------------

## 14. 투표 완료

모든 현재 활성 참가자의 투표가 제출되면 서버가 해당 라운드를 자동
종료하고 집계한다.

투표 종료 후 공개할 수 있는 정보:

-   후보별 최종 득표수
-   동률 여부
-   단독 최다 득표자가 있는 경우 해당 Player
-   재투표가 필요한 경우 재투표 대상 후보

개인별 voter → target 관계는 공개하지 않는다.

------------------------------------------------------------------------

## 15. 단독 최다 득표

한 명의 Player가 단독 최다 득표를 얻으면 해당 Player를 최종 지목자로
결정한다.

서버는 해당 Player가 실제 라이어인지 판정한다.

------------------------------------------------------------------------

## 16. 동률

최다 득표자가 2명 이상이면 즉시 재투표를 시작한다.

재투표 후보는 **직전 투표 라운드의 최다 득표 동률 후보만**이다.

예:

``` text
A 2표
B 2표
C 1표
D 0표
```

재투표 후보:

``` text
A
B
```

C와 D는 재투표 후보가 아니다.

------------------------------------------------------------------------

## 17. 재투표

재투표에서도 모든 활성 참가자가 투표한다.

자기 자신에게는 투표할 수 없다.

각 재투표는 새로운 `voteRound`를 사용한다.

예:

``` text
1차 투표: voteRound = 1
재투표:   voteRound = 2
재재투표: voteRound = 3
...
```

재투표에서 다시 동률이면 다시 재투표한다.

### 재투표 횟수

**재투표 횟수 제한은 없다.**

단독 최다 득표자가 나올 때까지 계속 반복한다.

### 랜덤 지목

**서버는 동률 후보 중 한 명을 랜덤으로 선택하지 않는다.**

다음 규칙은 존재하지 않는다.

``` text
최대 2회까지만 재투표
3번째 동률이면 랜덤 선정
최종 동률 후보 중 랜덤 지목
```

------------------------------------------------------------------------

## 18. 재투표 정보 공개

재투표 역시 일반 투표와 동일한 비밀투표 규칙을 따른다.

공개 가능:

-   재투표 라운드 번호
-   재투표 후보
-   투표 필요 인원
-   투표 완료 인원
-   Player별 제출 완료 여부
-   라운드 종료 후 후보별 최종 득표수

비공개:

-   누가 누구에게 투표했는지
-   투표 진행 중 후보별 현재 득표수
-   현재 1위

------------------------------------------------------------------------

## 19. 최종 지목자가 시민인 경우

최종 지목자가 실제 라이어가 아니면 시민 팀은 라이어 검거에 실패한
것이다.

이 경우:

1.  게임은 즉시 라이어 승리로 결정한다.
2.  실제 라이어를 공개한다.
3.  제시어를 공개할 수 있다.
4.  라이어의 최종 제시어 추측 단계는 진행하지 않는다.
5.  GameSession은 `FINISHED`로 진행한다.

------------------------------------------------------------------------

## 20. 최종 지목자가 라이어인 경우

최종 지목자가 실제 라이어라면 시민 승리로 즉시 확정하지 않는다.

라이어에게 마지막 제시어 추측 기회를 정확히 한 번 제공한다.

게임은 `LIAR_GUESS` 단계로 진행한다.

------------------------------------------------------------------------

## 21. 라이어 최종 제시어 추측

실제 라이어만 답안을 제출할 수 있다.

시민은 답안을 제출할 수 없다.

시민 화면에는 입력창이나 제출 버튼을 제공하지 않고 대기 상태만 표시한다.

라이어는 한 번만 답안을 제출할 수 있다.

제출 후 수정할 수 없다.

서버가 답안의 정답 여부를 판정한다.

MVP 기본 정규화 예:

-   앞뒤 공백 제거
-   대소문자 무시
-   연속 공백 정규화
-   필요한 경우 서버에 등록된 accepted answers 사용

Frontend에서 정답 여부를 직접 판정하지 않는다.

------------------------------------------------------------------------

## 22. 최종 승패

### 시민을 잘못 지목

``` text
라이어 승리
```

### 실제 라이어 지목 + 라이어가 제시어 정답

``` text
라이어 승리
```

### 실제 라이어 지목 + 라이어가 제시어 오답

``` text
시민 승리
```

------------------------------------------------------------------------

## 23. 게임 상태

기본 상태:

``` text
READY
ROLE_REVEAL
DISCUSSION
VOTING
VOTE_RESULT
REVOTING
LIAR_REVEAL
LIAR_GUESS
FINISHED
CANCELLED
```

서버가 상태 전이를 관리한다.

Frontend는 서버 상태를 기반으로 화면을 선택한다.

------------------------------------------------------------------------

## 24. 상태별 주요 행동

### READY

방장:

-   게임 시작

### ROLE_REVEAL

각 Player:

-   자신의 역할 확인
-   역할 확인 완료 제출

### DISCUSSION

방장:

-   투표 시작

일반 Player:

-   웹 행동 없음
-   오프라인 추리

### VOTING

아직 투표하지 않은 Player:

-   유효 후보 선택
-   투표 제출

이미 투표한 Player:

-   대기

### VOTE_RESULT

-   서버 결과 표시
-   단독 최다 득표면 판정 진행
-   동률이면 서버가 재투표 생성

### REVOTING

-   서버가 제공한 동률 후보만 대상으로 투표
-   다시 동률이면 계속 재투표

### LIAR_REVEAL

-   최종 지목자의 정체 결과 표시

### LIAR_GUESS

라이어:

-   답안 입력 및 1회 제출

시민:

-   대기

### FINISHED

-   최종 승패 표시
-   방장은 다음 게임 행동 선택 가능

------------------------------------------------------------------------

## 25. 연결 끊김

WebSocket 연결 손실만으로 즉시 Player를 Room에서 제거하지 않는다.

일시적인 연결 손실:

``` text
CONNECTED
→ DISCONNECTED
```

동일 `clientId`가 다시 연결되면 기존 Player로 복구한다.

------------------------------------------------------------------------

## 26. 투표 중 연결 끊김

투표 중 Player가 일시적으로 연결을 잃으면 일정 시간 재접속을 기다릴 수
있다.

장시간 복귀하지 않는 Player는 방장이 현재 GameSession에서 제외할 수
있다.

제외가 확정되면:

-   해당 Player는 현재 GameSession 투표 대상/필요 인원에서 제외
-   해당 Player가 이미 제출한 투표가 있다면 해당 투표는 무효 처리
-   필요한 투표 수를 다시 계산

정확한 연결 timeout 값은 별도 운영 설정으로 정할 수 있다.

------------------------------------------------------------------------

## 27. 라이어 이탈

실제 라이어가 명시적으로 나가거나 장시간 이탈하여 현재 GameSession에서
제외되어야 하는 경우:

``` text
GameSession = CANCELLED
```

게임 도중 새로운 라이어를 다시 선정하지 않는다.

------------------------------------------------------------------------

## 28. Host 이탈

방장의 일시적인 연결 끊김만으로 즉시 Host를 변경하지 않는다.

방장이 명시적으로 Room을 나가거나 장시간 복귀하지 않는 경우 새로운
Host를 선정할 수 있다.

새 Host는 현재 연결된 Player 중 기존 정책에 따라 선정한다.

------------------------------------------------------------------------

## 29. 재접속

재접속한 Client는:

``` text
roomId + clientId
```

기준으로 기존 Player를 복구한다.

복구 후 서버의 현재 state를 조회한다.

예:

-   이미 역할 확인 → 다시 확인 불가
-   이미 투표 → 다시 투표 불가
-   현재 재투표 → 현재 voteRound와 후보 표시
-   현재 LIAR_GUESS → 역할에 따라 입력 또는 대기
-   이미 FINISHED → 결과 표시

------------------------------------------------------------------------

## 30. 다음 게임

게임 종료 후 Room은 유지한다.

방장은 다음 중 하나를 선택할 수 있다.

-   같은 게임 다시하기
-   다른 게임 선택
-   Room 종료

같은 게임 다시하기는 새로운 GameSession을 만든다.

새 GameSession에서는 다음을 다시 선정한다.

-   라이어
-   제시어
-   첫 발언자

Player의 Room 참가 상태, 닉네임, 성별은 유지한다.

------------------------------------------------------------------------

## 31. 서버 권한 검증

서버는 모든 행동에서 최소한 다음을 검증한다.

-   Player가 Room에 속하는가
-   현재 GameSession 참가자인가
-   필요한 경우 Host인가
-   현재 phase에서 가능한 행동인가
-   이미 동일 행동을 완료하지 않았는가
-   역할상 가능한 행동인가
-   투표 후보가 유효한가
-   voteRound가 현재 라운드와 일치하는가

UI에서 버튼을 숨기는 것만으로 권한을 보장하지 않는다.

------------------------------------------------------------------------

## 32. 실시간 이벤트

대표 이벤트:

``` text
GAME_STARTED
ROLE_CHECKED
DISCUSSION_STARTED
VOTE_STARTED
PLAYER_VOTED
VOTE_COMPLETED
VOTE_RESULT
REVOTE_STARTED
LIAR_REVEALED
LIAR_GUESS_STARTED
LIAR_GUESS_SUBMITTED
GAME_FINISHED
GAME_CANCELLED
```

### PLAYER_VOTED

공개 가능:

``` text
playerId
submitted = true
```

공개 금지:

``` text
targetPlayerId
```

### VOTE_RESULT

후보별 최종 득표수는 포함할 수 있다.

개인별 voter → target 정보는 포함하지 않는다.

------------------------------------------------------------------------

## 33. 게임 결과에서 투표 정보

게임이 완전히 종료된 뒤에도 개인별 투표 내역은 공개하지 않는다.

최종 결과 화면에서 필요하다면 다음만 표시한다.

``` text
최종 라운드 후보별 득표수
최종 지목자
실제 라이어
제시어
라이어 최종 답안 (추측 단계가 있었던 경우)
승리 팀
```

## 36. 최종 불변 규칙

아래 두 규칙은 다른 절이나 요약에서 다르게 해석하지 않는다.

### 동률

> **동률이면 단독 최다 득표자가 나올 때까지 동률 후보를 대상으로 무제한
> 재투표한다. 서버는 동률을 랜덤으로 해결하지 않는다.**

### 투표 비밀

> **누가 누구에게 투표했는지는 투표 중, 라운드 종료 후, 재투표 중, 게임
> 종료 후를 포함해 항상 비공개다. 후보별 최종 득표수만 라운드 종료 후
> 공개할 수 있다.**
