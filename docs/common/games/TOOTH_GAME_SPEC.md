# NOOPI (누피) Tooth Game Specification

## 1. 게임 개요

- 표시 이름: **누피 콱!**
- 게임 타입: `TOOTH`
- 장르: 랜덤 / 벌칙 / 파티 미니게임
- 참가 인원: **2~8명**
- 예상 플레이 시간: 약 10초~1분

참가자는 서버가 정한 순서대로 누피의 이빨을 하나씩 누른다. 24개 중 정확히
하나는 숨겨진 꽝 이빨이다. 꽝 이빨을 누른 Player 한 명이 당첨되고 게임은
즉시 종료된다. 순위와 별도 승자는 두지 않는다.

게임 상태와 모든 판정의 최종 권한은 서버에 있다.

## 2. 참가 조건과 설정

- 최소 인원: 2명
- 최대 인원: 8명
- 모드: 개인전
- 별도 사용자 설정 없음

방장은 `config = {}`로 GameSession을 생성한다. 서버는 시작 시점의 정상 참가
Player가 2~8명인지 검증한다. 인원, 이빨 수, 꽝 수와 턴 규칙은 Client 설정으로
변경할 수 없다.

## 3. 이빨 구성

총 24개를 사용한다.

- 윗니 12개: `toothId` 1~12
- 아랫니 12개: `toothId` 13~24

각 줄의 번호는 화면을 바라보는 Player 기준 왼쪽에서 오른쪽 순서다. 이 번호는
API와 화면의 안정적인 식별자이며 꽝 여부를 의미하지 않는다.

각 이빨의 공개 상태는 `AVAILABLE` 또는 `SELECTED`다. 선택된 이빨은 다시
선택할 수 없다.

## 4. 게임 시작

방장이 GameSession 시작을 요청하면 서버는 하나의 원자적 처리 안에서 다음을
수행한다.

1. 참가 인원 2~8명 검증
2. 전체 참가자의 턴 순서를 무작위로 확정
3. 24개 중 꽝 이빨 정확히 1개를 무작위로 확정
4. 모든 이빨을 `AVAILABLE`로 초기화
5. 첫 번째 Player를 현재 턴으로 지정
6. GameSession을 `PLAYING`으로 전환

`bombToothId`는 서버 Runtime에만 보관하며 게임 종료 전 REST 응답과 WebSocket
이벤트에 포함하지 않는다.

## 5. 게임 상태

게임 phase는 다음과 같다.

``` text
READY
PLAYING
FINISHED
```

`PLAYING` 동안 서버는 턴 순서, 현재 턴 Player, 선택된 이빨, 남은 이빨 수와
가장 최근 선택 결과를 관리한다.

현재 요청 Player가 이빨을 선택할 수 있을 때만 `allowedActions`에
`SELECT_TOOTH`를 제공한다. Frontend는 `currentTurnPlayerId`만으로 행동 권한을
확정하지 않고 `allowedActions`를 기준으로 터치 UI를 제공한다.

## 6. 턴 진행

현재 턴 Player만 `AVAILABLE` 이빨 하나를 선택할 수 있다.

- 한 턴에 정확히 한 개만 선택한다.
- 턴 넘기기 기능은 없다.
- 같은 턴에 두 개 이상을 선택할 수 없다.
- 이미 선택된 이빨은 선택할 수 없다.
- 서버 응답 전까지 Client는 모든 이빨 입력을 잠근다.

서버는 요청마다 현재 GameSession, phase, 참가 여부, 현재 턴, 이빨 범위,
선택 여부와 중복 요청 여부를 다시 검증한다.

## 7. 안전한 이빨

선택한 이빨이 꽝이 아니면 서버는 다음을 원자적으로 처리한다.

1. 해당 이빨을 `SELECTED`로 변경
2. 결과를 `SAFE`로 확정
3. 턴 순서의 다음 Player를 현재 턴으로 지정
4. `TOOTH_SELECTED` 이벤트 발행

Client는 서버가 확정한 `SAFE` 결과로만 눌림과 `딸깍!` 연출을 재생한다.
Client가 이빨 위치나 남은 개수로 안전 여부 또는 다음 Player를 계산하지 않는다.

## 8. 꽝 이빨과 종료

선택한 이빨이 꽝이면 서버는 다음을 원자적으로 처리한다.

1. 해당 이빨을 `SELECTED`로 변경
2. 결과를 `BOMB`으로 확정
3. 선택한 Player를 `loserPlayer`로 확정
4. GameSession을 즉시 `FINISHED`로 전환
5. `TOOTH_SELECTED`와 공통 `GAME_FINISHED` 이벤트 발행

꽝 이후에는 다음 턴을 만들지 않는다. 결과 화면은 서버가 제공한
`loserPlayer`를 중심으로 `당첨!`, `누피에게 물렸습니다` 같은 표현을 사용한다.
1위~8위 순위나 별도 승자는 표시하지 않는다.

## 9. 정보 공개

게임 진행 중 공개할 수 있는 정보:

- 전체 턴 순서
- 현재 턴 Player
- 각 이빨의 `toothId`와 선택 여부
- 남은 이빨 수
- 서버가 확정한 가장 최근 `SAFE` 결과

게임 종료 전 공개하면 안 되는 정보:

- `bombToothId`
- 아직 선택하지 않은 이빨의 결과
- Client가 꽝 위치를 추론할 수 있는 내부 난수나 후보 정보

`BOMB`이 확정된 뒤에는 결과 연출을 위해 선택된 `toothId`와
`loserPlayer`를 전체 참가자에게 공개할 수 있다.

## 10. 동시 입력과 멱등성

이빨 선택은 Room 단위 동시성 경계 안에서 처리한다. Client는 첫 터치 즉시
모든 이빨 입력을 잠그고 자동 재시도하지 않는다.

요청은 `Idempotency-Key`를 사용한다. 동일 키의 재전송이 같은 이빨을 두 번
선택하거나 턴을 두 번 넘겨서는 안 된다. 서로 다른 요청이 동시에 도착해도
서버가 먼저 유효하게 처리한 현재 턴의 요청 하나만 상태를 변경할 수 있다.

응답을 확인하지 못하면 Client는 새 선택 요청을 보내기 전에 `/state`를 다시
조회한다.

## 11. 실시간 동기화와 재접속

WebSocket 이벤트는 상태 변경 알림이다. Client는 `TOOTH_SELECTED` 또는 공통
게임 이벤트 수신 후 `room-state` Query를 갱신한다.

새로고침 또는 재접속 후 `/state`로 다음을 복구한다.

- phase
- 턴 순서와 현재 턴 Player
- 24개 이빨의 선택 상태와 남은 개수
- 최근 선택 결과
- 종료된 경우 당첨 Player와 꽝 이빨
- 현재 Player의 `allowedActions`

과거 이벤트 재생이나 localStorage의 게임 상태에 의존하지 않는다.

## 12. 연결 종료와 이탈

연결 종료만으로 턴을 넘기거나 Player를 당첨 처리하지 않는다. 재접속을
기다리며 자동 턴 제한 시간은 V1에서 두지 않는다.

진행 중 참가자가 명시적으로 Room을 나가거나 영구 제외되면 GameSession을
`CANCELLED`로 전환한다. 남은 Player만으로 턴을 다시 계산하거나 이탈자를
당첨 처리하지 않는다.

## 13. 다시하기

`한 판 더`는 같은 Room과 Player를 유지한 채 새로운 `TOOTH` GameSession을
생성하고 시작한다. 새 GameSession에서는 24개 이빨, 꽝 위치와 전체 턴 순서를
모두 새로 초기화한다. 이전 게임의 선택과 꽝 위치는 영향을 주지 않는다.

## 14. Frontend 표현 원칙

화면 중앙에 입을 크게 벌린 누피와 실제 `<button>`인 윗니 12개, 아랫니
12개를 배치한다. 별도의 선택 버튼은 만들지 않는다.

- 내 차례: 선택 가능한 이빨과 `이빨 하나를 눌러주세요!`
- 다른 Player 차례: 이빨 입력을 제공하지 않고 대기 문구 표시
- 요청 처리 중: 모든 이빨 입력 잠금
- `SAFE`: 눌림 후 0.2~0.4초 안에 `딸깍!` 연출
- `BOMB`: 짧은 정적, 표정 변화, 입 닫힘, 흔들림과 당첨 결과 연출

효과음은 음소거할 수 있어야 하며 브라우저 정책을 따른다. 진동은 지원하는
기기에서만 보조 피드백으로 사용하고, 소리나 진동만으로 결과를 전달하지 않는다.
`prefers-reduced-motion` 환경에서는 과도한 흔들림과 이동을 줄이고 결과 문구를
즉시 제공한다.

## 15. 모듈 경계

Frontend는 `features/games/tooth/`, Backend는 `game/tooth` 아래에 독립적으로
구성한다. Room과 다른 게임 모듈은 꽝 선정, 이빨 선택, 턴과 당첨 판정을
알지 않는다.

## 16. 서버 책임 요약

서버가 다음을 결정하고 검증한다.

- 참가 인원 2~8명
- 무작위 턴 순서
- 24개 이빨과 꽝 이빨 정확히 1개
- 현재 턴과 선택 권한
- 중복·동시 선택 방지
- 안전/꽝 결과
- 다음 턴
- 당첨 Player와 즉시 종료
- 다시하기의 완전한 재초기화

Frontend는 이빨 선택 의도만 전달하고 결과를 자체 계산하거나 optimistic하게
확정하지 않는다.
