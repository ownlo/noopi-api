# NOOPI (누피) UnderMine Game Specification

> 기준: 원작 기본판의 핵심 규칙을 NOOPI 모바일 웹에 맞게 재구성  
> NOOPI 변경 규칙: **규칙상 낼 수 있는 카드가 한 장도 없을 때만 카드 버리기 가능**  

## 1. 게임 개요

- 표시 이름: **언더마인 (UnderMine)**
- 내부 게임 타입: `UNDERMINE`
- 장르: 정체 은닉 / 길 연결 / 카드 전략 / 심리전
- 참가 인원: **3~10명**
- 전체 라운드: **3라운드**
- 예상 플레이 시간: 약 20~40분
- 대화 방식: 같은 공간에서 직접 대화하며 별도 인게임 채팅은 제공하지 않는다.

플레이어는 매 라운드 `광부` 또는 `방해꾼` 역할을 비밀리에 배정받는다.

- 광부는 출발 카드에서 진짜 보물 목적지까지 끊기지 않은 길을 완성한다.
- 방해꾼은 정체를 숨기면서 라운드가 끝날 때까지 보물 길 완성을 막는다.
- 라운드 승리 진영은 금을 얻는다.
- 3라운드 종료 후 누적 금점수가 가장 높은 Player가 최종 승리한다.

역할, 손패, 개인 정찰 결과와 금 카드는 개인 정보다. 보드, 현재 턴, 공개된
목적지, Player별 고장 장비와 손패 수는 모든 참가자에게 공개한다.

## 2. NOOPI 적용 원칙

게임 진행과 판정의 최종 권한은 서버에 있다.

서버는 최소한 다음을 결정하고 검증한다.

- 라운드별 역할 카드 구성, 셔플과 배정
- 사용되지 않고 숨겨지는 역할 카드
- 길·행동 카드 셔플, 초기 손패와 드로우
- 금 카드 셔플과 지급
- 턴 순서와 현재 턴
- 현재 Player가 실제로 낼 수 있는 카드와 대상 후보
- 길 카드 회전과 배치 유효성
- 장비 고장과 수리
- 파괴 대상과 제거 결과
- 지도 확인 결과
- 목적지 공개와 보물 도달 여부
- 카드 버리기 가능 여부
- 라운드 종료, 진영 승리와 금 지급
- 3라운드 누적 점수와 최종 공동 우승자

Frontend는 서버가 제공한 현재 상태와 행동 후보만 표현하며 경로, 역할, 승리,
점수 또는 다음 턴을 자체 계산하지 않는다.

## 3. 원작과 다른 NOOPI 규칙

원작에서는 낼 수 있는 카드가 있어도 원하는 카드 1장을 뒤집어 버리고 턴을
넘길 수 있다. NOOPI에서는 이 자유 버리기를 사용하지 않는다.

### 제한 버리기

현재 손패에 **규칙상 실행 가능한 카드가 한 장도 없을 때만** 카드 1장을
버릴 수 있다.

실행 가능한 카드는 다음을 모두 포함한다.

- 현재 장비 상태에서 유효한 위치에 배치할 수 있는 길 카드
- 유효한 Player에게 적용할 수 있는 장비 고장 카드
- 실제로 고장 난 장비를 고칠 수 있는 수리 카드
- 제거 가능한 길 카드가 있을 때의 파괴 카드
- 아직 뒷면인 목적지가 있을 때의 지도 카드

위 카드 중 하나라도 낼 수 있으면 `DISCARD_CARD`는 허용하지 않는다. 어떤
진영에 불리하거나 원하지 않는 카드라는 이유로 버릴 수 없다.

버리는 카드는 다른 Player에게 앞면을 공개하지 않는다. 공개 정보에는 버린
Player와 버리기 행동만 포함한다.

## 4. 역할 구성

매 라운드 시작 시 참가 인원에 맞춰 다음 역할 카드 묶음을 만든다.

| 참가 인원 | 광부 카드 | 방해꾼 카드 | 실제 방해꾼 수 |
| --- | ---: | ---: | ---: |
| 3명 | 3장 | 1장 | 0~1명 |
| 4명 | 4장 | 1장 | 0~1명 |
| 5명 | 4장 | 2장 | 1~2명 |
| 6명 | 5장 | 2장 | 1~2명 |
| 7명 | 5장 | 3장 | 2~3명 |
| 8명 | 6장 | 3장 | 2~3명 |
| 9명 | 7장 | 3장 | 2~3명 |
| 10명 | 7장 | 4장 | 3~4명 |

역할 카드는 참가 인원보다 항상 1장 많다. 서버는 이를 섞어 각 Player에게
1장씩 지급하고 남은 1장은 해당 라운드가 끝날 때까지 공개하지 않는다.

따라서 Player는 방해꾼 카드의 최대 수는 알 수 있지만 이번 라운드의 실제
방해꾼 수는 확신할 수 없다. 방해꾼도 다른 방해꾼의 정체를 알 수 없다.

역할은 매 라운드 새로 섞어 배정하며 이전 라운드 역할과 무관하다.

## 5. 카드 구성

### 5.1 길 카드

길 카드 묶음은 총 44장이다.

- 출발 카드 1장
- 목적지 카드 3장
  - 보물 1장
  - 돌 2장
- 실제 손패와 드로우 덱에 사용하는 길 카드 40장

길 카드에는 상·하·좌·우 면별 통로 유무와 카드 내부의 연결 관계가 정의된다.
막다른 길 카드도 정상 길 카드이며 배치 규칙을 만족하면 사용할 수 있다.

길 카드는 세로 방향을 유지하며 `0°` 또는 `180°`로 놓을 수 있다. `90°`와
`270°` 회전은 허용하지 않는다.

### 5.2 행동 카드

행동 카드는 총 27장이다.

| 종류 | 수량 | 효과 |
| --- | ---: | --- |
| 장비 고장 | 9장 | 곡괭이·랜턴·광차 각 3장 |
| 장비 수리 | 9장 | 대상의 가장 먼저 고장 난 장비 1개 수리 |
| 지도 | 6장 | 뒷면 목적지 하나를 본인만 확인 |
| 파괴 | 3장 | 출발·목적지를 제외한 길 카드 하나 제거 |

길 카드 40장과 행동 카드 27장을 합친 67장이 매 라운드의 플레이 덱이 된다.

### 5.3 금 카드

금 카드는 28장이며 카드마다 1~3개의 금이 표시된다. 금 1개 카드 16장, 금 2개
카드 8장, 금 3개 카드 4장으로 구성하고 플레이 덱과 별도로 관리한다.

Player가 받은 금 카드와 카드별 값은 게임 종료 전까지 본인에게만 보인다.
다른 Player에게는 라운드별 획득 여부나 누적 금점수를 공개하지 않는다.

## 6. 초기 설정

### 6.1 보드 좌표

서버 좌표는 출발 카드를 `(0, 0)`으로 한다.

- 위쪽 목적지: `(8, -2)`
- 가운데 목적지: `(8, 0)`
- 아래쪽 목적지: `(8, 2)`

세 목적지 카드는 무작위로 섞어 뒷면으로 배치한다. 출발과 목적지 사이에는
가로 방향으로 카드 7장이 들어갈 공간이 있고, 목적지 사이에는 카드 한 칸의
간격이 있다.

출발 카드는 보드의 왼쪽 경계다. 길 카드는 `x >= 0`인 좌표에만 놓을 수 있으며
출발점 왼쪽인 `x < 0`에는 놓을 수 없다.

길은 이 왼쪽 경계를 제외하고 기본 5×9 영역 바깥으로도 확장할 수 있다.
Frontend 보드는 확대·축소와 드래그 이동을 제공하되 가로 스크롤이 페이지
전체에 발생하지 않게 한다.

### 6.2 초기 손패

| 참가 인원 | 1인당 초기 손패 |
| --- | ---: |
| 3~5명 | 6장 |
| 6~7명 | 5장 |
| 8~10명 | 4장 |

초기 손패 지급 후 남은 플레이 카드가 드로우 덱이 된다.

### 6.3 턴 순서

NOOPI에는 나이 정보가 없으므로 첫 라운드는 서버가 전체 Player의 원형 턴
순서를 무작위로 정한다. 첫 Player도 무작위로 선택한다.

다음 라운드는 직전 라운드의 마지막 유효 행동 Player 다음 순서의 Player부터
시작한다. 원형 턴 순서는 GameSession 동안 유지한다.

## 7. Phase와 라운드 진행 단계

``` text
READY
→ ROLE_REVEAL
→ PLAYING
→ ROUND_RESULT
→ 광부 승리 시 GOLD_SELECTION
→ 금 지급 완료 후 ROUND_RESULT
→ 다음 라운드 ROLE_REVEAL
→ 3라운드 종료 후 FINISHED
```

`ROLE_REVEAL`은 역할을 아직 확인하지 않은 Player의 역할 확인 화면과 이미
확인한 Player의 대기 화면을 함께 표현한다. 별도 `ROLE_WAIT` phase를 만들지
않는다. 방해꾼 승리처럼 금 선택이 필요 없는 경우 `GOLD_SELECTION`을 거치지
않는다.

### 7.1 역할 확인

각 Player는 본인의 역할만 확인하고 `역할 확인 완료`를 제출한다. 전원이 확인을
완료하면 서버가 첫 턴을 시작한다.

역할 확인 중에는 손패 행동을 제공하지 않는다. 다른 Player에 대해서는 역할
확인 완료 여부만 표시하고 역할은 공개하지 않는다.

### 7.2 한 턴의 행동

현재 Player는 다음 중 서버가 허용한 행동 하나를 수행한다.

1. 길 카드 배치
2. 장비 고장 카드 사용
3. 장비 수리 카드 사용
4. 파괴 카드 사용
5. 지도 카드 사용
6. 낼 수 있는 카드가 없을 때 카드 1장 버리기

행동이 확정되면 드로우 덱이 남아 있는 경우 카드 1장을 받아 손패에 추가한다.
이후 서버가 라운드 종료 여부를 판정하고, 계속 진행하면 다음 Player에게 턴을
넘긴다.

모든 행동 요청에는 `Idempotency-Key`를 사용한다. 요청 처리 중 Client는 손패,
대상과 확인 버튼을 모두 잠가 중복 요청을 막는다.

## 8. 길 카드 배치

현재 Player에게 고장 난 장비가 하나라도 있으면 길 카드를 놓을 수 없다.
행동 카드 사용과 제한 버리기는 가능하다.

길 카드는 다음 조건을 모두 만족해야 한다.

1. `x >= 0`인 비어 있는 정수 좌표에 놓는다. `x < 0`은 허용하지 않는다.
2. 기존 길 카드 또는 출발 카드와 상하좌우 중 한 면 이상 맞닿는다.
3. 맞닿는 모든 면의 통로 유무가 일치한다.
4. 배치된 카드의 통로가 출발 카드까지 끊기지 않고 연결된다.
5. 세로 방향을 유지하며 `0°` 또는 `180°`만 사용한다.

파괴로 출발점과 분리된 카드들은 보드에 남는다. 그러나 다시 출발점과
연결되기 전까지 새 카드 배치의 연결 근거와 목적지 도달 경로로 사용할 수 없다.

서버는 손패의 길 카드별 `placeablePlacements`를 좌표와 회전값으로 제공한다.
Frontend는 전체 보드를 이용해 후보를 다시 계산하지 않는다.

## 9. 장비 고장

장비는 다음 세 종류다.

- `PICKAXE`: 곡괭이
- `LANTERN`: 랜턴
- `CART`: 광차

장비 고장 카드는 `곡괭이 고장`, `랜턴 고장`, `광차 고장`이 각각 별개의
카드다. 카드를 낸 뒤 장비 종류를 선택하지 않으며 카드 앞면에 표시된 장비만
고장 낸다. 해당 카드는 본인을 제외한 다른 Player에게만 사용할 수 있다. 대상에게
같은 종류의 고장이 이미 적용되어 있으면 사용할 수 없다. 서로 다른 종류의
고장은 동시에 적용할 수 있다.

고장 장비가 하나 이상 있는 Player는 길 카드를 배치할 수 없지만 행동 카드는
사용할 수 있다. 역할과 관계없이 모든 Player에게 같은 규칙을 적용한다.

Player별 고장 장비 종류는 모두에게 공개한다.

## 10. 장비 수리

수리 카드는 장비 종류가 구분되지 않는 공통 카드이며 본인 또는 다른 Player에게
사용할 수 있다. 대상 Player의 `brokenTools`에서 가장 먼저 고장 난 장비 1개를
서버가 제거한다. Frontend는 수리할 장비를 별도로 선택하거나 결정하지 않는다.

- 고장 장비가 하나 이상 있는 Player만 대상으로 선택할 수 있다.
- 한 번의 행동으로 장비 하나만 수리한다.
- 고장 장비가 없는 Player에게는 수리 카드를 낼 수 없다.

사용한 수리 카드와 제거된 고장 카드는 공개 버림 더미로 이동한다.

## 11. 파괴

파괴 카드는 현재 보드의 일반 길 카드 1장을 제거한다.

제거할 수 없는 카드:

- 출발 카드
- 뒷면 또는 공개된 목적지 카드

길 제거로 다른 카드가 출발점에서 끊겨도 제거 자체는 유효하다. 끊긴 카드들은
보드에 남으며 적절한 길이 놓이면 다시 연결될 수 있다. 제거된 자리는 이후
유효한 길 카드로 채울 수 있다.

서버는 현재 Player에게 `removablePathCardIds`를 제공한다.

## 12. 지도

지도 카드는 아직 공개되지 않은 목적지 하나를 선택해 그 정체를 본인만 확인한다.

Frontend에서 지도 카드를 선택하면 별도의 목적지 선택 목록을 표시하지 않는다.
서버가 `cardOptions`로 제공한 지도 대상만 게임판 위에서 강조하며, Player는 판에
놓인 목적지 카드를 직접 선택한다.

- 보물인지 돌인지 다른 Player에게 자동 공개하지 않는다.
- 같은 Player가 이전에 확인한 뒷면 목적지를 다시 선택하는 것도 허용한다.
- 다른 Player가 같은 목적지를 지도 카드로 봤더라도 선택할 수 있다.
- 실제 대화로 결과를 공유하거나 거짓말할 수 있다.
- 공개된 목적지는 지도 대상으로 선택할 수 없다.

사용한 지도 카드는 공개 버림 더미로 이동한다. 지도 대상은 공개하지만 확인
결과는 해당 Player에게만 전달한다.

재접속 후에도 본인이 이번 라운드에 확인한 목적지 결과를 복원한다.

## 13. 제한 버리기 판정

서버는 턴 시작과 상태 변경 후 현재 손패 전체의 유효 행동을 계산한다.

``` text
legalPlayableCardIds가 비어 있음
→ discardAllowed = true

legalPlayableCardIds에 카드가 하나 이상 있음
→ discardAllowed = false
```

`discardAllowed = true`이면 손패의 카드 중 원하는 1장을 뒷면으로 버린다.
버린 카드의 식별자와 종류는 본인과 서버만 알며 Room 전체 상태나 실시간
이벤트에 포함하지 않는다.

손패가 0장인 Player의 턴은 서버가 자동으로 건너뛴다.

## 14. 목적지 공개

길 카드 배치 후 출발 카드에서 해당 목적지까지 끊기지 않은 통로가 만들어지면
서버가 목적지를 공개한다.

목적지는 새로 놓인 길 카드와 통로가 이어지도록 서버가 방향을 확정한다. 공개된
목적지의 다른 면이 인접 카드와 일치하지 않는 드문 경우에는 목적지 카드에
한해서 인접 면 불일치를 허용한다.

### 돌 목적지

- 앞면을 모두에게 공개한다.
- 라운드는 계속된다.
- 공개된 목적지는 이후 보드의 길 일부로 사용할 수 있다.

### 보물 목적지

- 앞면을 모두에게 공개한다.
- 광부 진영 승리로 라운드를 즉시 종료한다.
- 해당 길 카드를 놓은 Player를 라운드의 보물 도달 Player로 기록한다.

한 번의 배치로 둘 이상의 목적지에 도달하면 서버가 모두 공개한다. 그중 보물이
있으면 즉시 광부 승리로 처리한다.

## 15. 라운드 종료

### 15.1 광부 승리

출발 카드에서 보물 목적지까지 끊기지 않은 길이 완성되면 즉시 광부 진영이
승리한다.

### 15.2 방해꾼 승리

드로우 덱이 비어 있고, 손패가 남은 모든 Player에게 실행 가능한 카드가 하나도
없으면 방해꾼 진영이 승리한다.

서버는 이 조건이 충족되면 불필요한 버리기 턴을 반복하지 않고 라운드를 즉시
종료한다.

실제 방해꾼이 0명인 라운드에서 광부가 실패하면 어느 Player도 금을 받지 않는다.

### 15.3 역할 공개

라운드가 종료되면 다음 정보를 모두에게 공개한다.

- 전체 Player의 이번 라운드 역할
- 사용되지 않고 숨겨졌던 역할 카드
- 보물 목적지 위치
- 라운드 승리 진영

## 16. 금 지급

### 16.1 광부 승리 시

서버는 이번 라운드에 실제 배정된 광부 수만큼 금 카드를 비공개로 뽑는다.

보물에 도달하는 마지막 길 카드를 놓은 Player가 광부라면 그 광부가 먼저 카드
1장을 선택한다. 해당 Player가 방해꾼이라면 원형 턴 순서의 역방향에서 가장
가까운 광부부터 선택한다. 이후 같은 방향의 다음 광부가 남은 카드 중 1장을
선택하며, 모든 광부가 1장씩 받을 때까지 반복한다. 방해꾼은 선택 순서에서
제외한다.

금 선택 단계에서는 역할이 이미 공개되어 있으므로 선택 순서를 모든 참가자에게
표시할 수 있다. 각 금 카드의 값과 선택 결과는 선택한 Player에게만 보인다.

### 16.2 방해꾼 승리 시

실제 방해꾼 수에 따라 각 방해꾼에게 다음 금점수를 지급한다.

| 실제 방해꾼 수 | 방해꾼 1명당 금점수 |
| --- | ---: |
| 1명 | 4점 |
| 2~3명 | 3점 |
| 4명 | 2점 |

서버는 남은 금 카드 묶음에서 지급 점수와 합계가 정확히 일치하는 카드 조합을
무작위로 정해 지급한다. 같은 라운드의 모든 방해꾼에게 동일한 점수를 지급하며,
개별 카드와 누적 금점수는 해당 Player에게만 공개한다.

## 17. 다음 라운드

라운드 결과와 금 지급이 끝나면 방장이 `다음 라운드`를 시작한다.

새 라운드에서는 다음을 모두 초기화한다.

- 전체 역할과 숨겨진 역할 카드
- 손패와 드로우 덱
- 출발점 이외의 보드
- 목적지 배치와 공개 상태
- 개인 지도 확인 기록
- Player별 고장 장비
- 최근 행동

누적 금 카드와 원형 턴 순서는 유지한다.

3라운드 결과와 금 지급이 끝나면 GameSession을 `FINISHED`로 전환한다.

## 18. 최종 승리

서버는 각 Player가 3라운드 동안 획득한 금점수를 합산한다. 가장 높은 점수의
Player가 최종 승리하며 동점이면 공동 우승한다.

최종 순위는 동일한 금점수의 Player에게 같은 `rank`를 부여하는 경쟁 순위
방식을 사용한다. 공동 순위 다음 번호는 공동 인원만큼 건너뛴다. 예를 들어
금점수가 `9, 9, 5`이면 순위는 `1, 1, 3`이다.

최종 결과 화면에는 다음을 공개한다.

- Player별 총 금점수
- 라운드별 역할과 획득 금점수
- 최종 우승자 또는 공동 우승자

## 19. 공개 정보와 개인 정보

### 19.1 진행 중 공개 정보

- 현재 라운드와 phase
- 길 보드와 각 카드의 위치·회전
- 공개된 목적지
- 원형 턴 순서와 현재 턴 Player
- Player별 손패 수
- Player별 고장 장비
- 드로우 덱 남은 카드 수
- 사용되어 공개 버림 더미로 이동한 카드와 비공개 버리기 횟수
- 직전 행동의 Player, 행동 종류와 공개 대상
- 역할 확인 완료 여부

### 19.2 본인에게만 공개

- 현재 역할
- 손패 카드
- 손패 카드별 서버 확정 행동 후보
- 지도 카드로 확인한 목적지 결과
- 획득한 금 카드와 현재 누적 금점수

### 19.3 라운드 종료 후 공개

- 이번 라운드 전체 역할
- 사용되지 않은 역할 카드
- 보물 위치
- 라운드 승리 진영

다른 Player의 손패와 지도 결과는 라운드 종료 후에도 공개하지 않는다.

## 20. 허용 행동과 후보

개인화된 서버 상태는 최소한 다음 행동을 구분한다.

``` text
CHECK_ROLE
PLAY_CARD
DISCARD_CARD
SELECT_GOLD
START_NEXT_ROUND
```

카드별 `cardOptions.actionType`은 `PLACE_PATH`, `BREAK_TOOL`, `REPAIR_TOOL`,
`DESTROY_PATH`, `USE_MAP`을 사용한다. 서버는 `allowedActions`와 함께 카드별
후보를 반환한다.

- 길 카드: 좌표와 `0 | 180` 회전 후보
- 장비 고장: Player와 장비 후보
- 장비 수리: 고장 장비가 하나 이상 있는 Player 후보
- 파괴: 제거 가능한 길 카드 후보
- 지도: 확인 가능한 목적지 후보
- 버리기: `allowedActions`에 `DISCARD_CARD`가 있을 때의 본인 손패 카드

Frontend는 전체 공개 상태를 바탕으로 후보를 추가하거나 제거하지 않는다.

## 21. 모바일 UX

화면은 세 영역을 중심으로 구성한다.

1. 상단: 라운드, 현재 턴, 덱 수, 내 역할 요약
2. 중앙: 이동·확대 가능한 길 보드
3. 하단: 가로 스크롤 가능한 내 손패와 현재 행동 안내

길 카드 선택 흐름:

``` text
카드 선택
→ 0°/180° 방향 전환
→ 서버가 제공한 배치 후보 강조
→ 위치 선택
→ 미리보기와 확인
→ 서버 확정
```

행동 카드 선택 시 유효한 Player, 장비, 길 카드 또는 목적지만 강조한다.
다른 Player의 턴에는 손패를 확인할 수 있지만 행동 입력은 제공하지 않는다.

비밀 정보를 표시하는 역할·지도·금 카드 화면에는 `길게 눌러 확인` 또는 명시적인
가림막 UI를 사용해 옆 사람에게 우연히 노출되는 일을 줄인다.

## 22. 실시간 동기화와 재접속

WebSocket 이벤트는 상태 변경 알림이며 게임 상태의 영구 저장소가 아니다.
Client는 관련 이벤트 수신 후 개인화된 Room `/state`를 다시 조회한다.

새로고침 또는 재접속 시 서버에서 다음을 복원한다.

- 현재 라운드와 phase
- 본인 역할과 역할 확인 여부
- 본인 손패와 행동 후보
- 길 보드와 목적지 상태
- 턴 순서와 현재 턴
- 전체 Player의 고장 장비
- 본인의 지도 확인 기록
- 드로우 덱과 손패 수
- 본인의 금 카드와 누적 점수
- 라운드 또는 최종 결과

진행 중 연결 종료만으로 턴을 넘기거나 Player를 제거하지 않는다. V1에는 턴 제한
시간과 자동 카드 사용을 두지 않는다. GameSession 참가자가 명시적으로 Room을
나가거나 영구 제외되면 GameSession을 `CANCELLED`로 종료한다.

## 23. 추천 실시간 이벤트

``` text
UNDERMINE_ROLE_CHECKED
UNDERMINE_CARD_PLAYED
UNDERMINE_PATH_DESTROYED
UNDERMINE_GOAL_REVEALED
UNDERMINE_TURN_CHANGED
UNDERMINE_ROUND_FINISHED
UNDERMINE_GOLD_SELECTION_CHANGED
UNDERMINE_ROUND_STARTED
```

Room 전체 이벤트에는 역할, 손패, 지도 결과, 금 카드 값과 같이 비공개인 정보를
포함하지 않는다. 이벤트 수신 후 개인화된 `/state`로 최신 상태를 조회한다.

## 24. 필수 Mock 시나리오

- 3~10명 시작 인원 검증
- 실제 방해꾼이 0명인 3·4인 라운드
- 방해꾼이 최대 수보다 한 명 적은 라운드
- 역할 확인 대기와 전체 확인 후 시작
- 길 카드 0°/180° 배치
- 인접 면 불일치 배치 거절
- 출발점과 연결되지 않은 배치 거절
- 막다른 길과 우회 길
- 장비 한 종류 고장과 길 배치 차단
- 서로 다른 복수 장비 고장
- 가장 먼저 고장 난 장비 자동 수리
- 유효 대상이 없는 고장·수리 카드
- 파괴로 핵심 길 제거
- 파괴로 분리된 길의 재연결
- 지도 결과 개인 공개와 재접속 복구
- 같은 목적지 중복 정찰
- 낼 수 있는 카드가 있어 버리기 거절
- 모든 카드가 불가능해 버리기 허용
- 덱 소진 후 빈 손패 Player 자동 건너뛰기
- 돌 목적지 공개 후 계속 진행
- 보물 목적지 도달과 광부 승리
- 덱 소진·전체 행동 불가와 방해꾼 승리
- 방해꾼 0명인데 광부가 실패한 결과
- 광부 금 카드 순차 선택
- 방해꾼 수별 금 지급
- 다음 라운드 역할·보드·손패 초기화
- 3라운드 최종 단독 우승과 공동 우승
- 연결 끊김, 새로고침과 재접속
- 현재 턴 Player 이탈로 GameSession 취소
- 중복 요청과 동시에 도착한 행동 하나만 처리

## 25. V1 제외 범위

- 확장판 역할과 카드
- 사용자 제작 카드
- 카드 수량·역할 비율·라운드 수 사용자 설정
- AI Player
- 게임 중 텍스트·음성 채팅
- 턴 제한 시간과 자동 행동
- 관전자 중도 참가
- 게임 진행 중 Player 교체

## 26. 저작권·브랜딩 주의

이 기획은 원작의 규칙 구조를 참고한 초안이다. 실제 서비스 출시 전에는 게임명,
카드 명칭, 카드 구성, 일러스트와 UI 표현에 대한 사용 권한을 검토해야 한다.
원작 카드 이미지나 설명문을 그대로 사용하지 않고 NOOPI 고유의 명칭과 시각
자산을 제작한다.

## 27. 구현 전 추가 산출물

이 문서를 정식 게임 SPEC으로 승격하기 전에 다음 자료를 별도로 확정한다.

- NOOPI 고유 길 카드 40장의 `cardType`, 내부 통로와 수량 카탈로그
- 카드·역할·장비·보물의 고유 일러스트와 에셋 식별자
- 개인화된 게임 상태 DTO와 행동 요청/응답 DTO
- 동시 행동, 중복 요청과 상태 충돌 오류 코드
- 모바일 보드의 최소·최대 확대 비율과 자동 포커스 정책

카드 카탈로그는 Frontend에서 승리 또는 배치 가능 여부를 판정하기 위한 데이터가
아니다. 서버 판정 결과를 동일한 모양으로 렌더링하기 위한 표현 계약으로만 쓴다.
