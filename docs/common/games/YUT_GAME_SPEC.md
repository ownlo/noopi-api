# NOOPI (누피) 윷놀이 Game Specification

## 1. 목적과 범위

NOOPI 윷놀이는 2~4명이 각자의 스마트폰으로 같은 윷판을 보며 진행하는
실시간 멀티플레이 게임이다. 개인전과 2:2 팀전을 지원한다. 개인전은 자신의
말 4개를 모두 완주한 순서대로 순위를 정하며 마지막 한 명만 남으면 꼴등으로
자동 확정한다. 팀전은 팀의 말 4개를 먼저 모두 완주하면 승리한다.

게임 상태와 판정의 최종 권한은 서버에 있다. Client는 현재 Player에게
허용된 행동의 의도만 전달하고 윷 결과, 경로, 말 위치, 업기, 잡기, 완주,
승자를 계산하거나 확정하지 않는다.

## 2. 게임 모드와 참가 인원

| 모드 | 인원 | 구성 | 말 소유 |
| --- | ---: | --- | --- |
| `INDIVIDUAL` | 2 | 1:1 | Player별 4개 |
| `INDIVIDUAL` | 3 | 1:1:1 | Player별 4개 |
| `INDIVIDUAL` | 4 | 1:1:1:1 | Player별 4개 |
| `TEAM` | 4 | 누피팀 2:2 데이팀 | 팀별 공유 말 4개 |

1인, 5인 이상, 3:3 이상 팀전은 V1에서 지원하지 않는다.

방장은 GameSession 생성 시 `INDIVIDUAL` 또는 `TEAM`을 선택한다. 개인전은
2~4명일 때 시작할 수 있다. 팀전은 정확히 4명이며 양 팀이 각각 2명일 때만
시작할 수 있다.

## 3. 팀 선택

팀전 GameSession을 만들면 `TEAM_SELECT` 단계로 진입한다. 팀은 다음 두
값으로 고정한다.

- `NOOPI`: 🐈‍⬛ 누피팀
- `DAY`: 🔵 데이팀

각 Player는 자신의 스마트폰에서 팀을 직접 선택한다. 팀별 정원은 2명이고
선착순이다. 팀 구성과 소속 Player는 모두에게 공개하며 변경 즉시 실시간으로
동기화한다.

게임 시작 전에는 자리가 있는 다른 팀으로 변경할 수 있다. 서버는 팀 선택과
변경을 원자적으로 처리한다. 변경 대상 팀이 이미 가득 찬 경우 요청을
실패시키고 기존 팀을 유지한다. 게임 시작 후에는 팀을 변경할 수 없다.

## 4. 게임과 턴 상태

게임 phase는 다음과 같다.

``` text
READY
TEAM_SELECT
PLAYING
FINISHED
```

개인전은 `TEAM_SELECT`를 사용하지 않고 `READY`에서 시작한다.

`PLAYING`의 턴 phase는 다음과 같다.

``` text
WAITING_THROW
THROWING
WAITING_MOVE
WAITING_PATH_SELECTION
MOVING
```

`THROWING`과 `MOVING`은 서버 처리 및 짧은 연출을 위한 상태다. 경로 선택이
필요하지 않으면 `WAITING_PATH_SELECTION`을 거치지 않는다.

## 5. 말 상태와 소유

말은 다음 상태 중 하나다.

``` text
READY
ON_BOARD
FINISHED
```

- `READY`: 아직 출발하지 않았거나 잡혀 출발점으로 돌아온 말
- `ON_BOARD`: 윷판 위에 있는 말
- `FINISHED`: 도착점을 통과하여 완주한 말

개인전에서는 Player가 자신의 말 4개를 소유한다. 팀전에서는 팀이 말 4개를
공유하며 현재 턴 Player는 소속 팀의 이동 가능한 말 또는 업힌 말 그룹을
이동할 수 있다.

## 6. 턴 순서

게임 시작 시 서버가 최초 순서를 결정한다.

- 개인전: 참가 Player 단위로 순환한다.
- 팀전: 양 팀이 반드시 번갈아 행동하도록 각 팀의 Player를 교차 배치한다.
  먼저 시작할 팀은 서버가 무작위로 정할 수 있다.

현재 턴의 Player만 윷 던지기, 이동권 선택, 말 선택, 경로 선택을 할 수
있다. 다른 Player에게는 현재 턴 Player를 표시하고 조작 UI를 제공하지
않는다.

개인전에서 말 4개를 모두 완주한 Player는 순위가 확정되며 이후 턴 순서에서
제외된다. 남은 Player는 기존 상대 순서를 유지하여 게임을 계속한다. 순위가
확정된 Player는 게임이 끝날 때까지 윷판과 진행 상황을 보는 관전 상태가 된다.

## 7. 윷 던지기와 결과

V1 결과와 이동 수는 다음과 같다.

| 결과 | 코드 | 이동 수 |
| --- | --- | ---: |
| 낙 | `NAK` | 0 |
| 빽도 | `BACK_DO` | -1 |
| 도 | `DO` | 1 |
| 개 | `GAE` | 2 |
| 걸 | `GEOL` | 3 |
| 윷 | `YUT` | 4 |
| 모 | `MO` | 5 |

네 윷가락 중 하나는 앞면에 누피 캐릭터가 표시된 특수 윷가락이다. 특수 윷가락만
앞면이고 나머지 세 개가 뒷면이면 `BACK_DO`다. 특수 윷가락이 뒷면이고 나머지
윷가락 중 하나만 앞면이면 일반 `DO`다. 서버는 네 윷가락의 앞뒤를 각각 독립적으로
결정한 뒤 표시 여부와 앞면 수로 결과를 판정한다. 결과 코드를 균등 확률로 선택하지
않는다. 윷가락 조합 판정 전에 서버가 **5% 확률**로 낙을 확정할 수 있다.

낙이면 그 던지기에 대한 이동권을 생성하지 않고 남은 추가 던지기는 종료한다.
해당 턴에 먼저 얻었지만 아직 사용하지 않은 이동권은 유지하여 현재 Player가
모두 사용한다. 기존 이동권이 하나도 없을 때만 즉시 다음 Player의 턴으로 넘어간다.
Frontend는 서버의 `NAK` 결과를 받으면 윷가락이 윷판 바깥으로 튕겨 나가는 짧은
연출을 보여준다. 기존 이동권이 정확히 하나라면 해당 이동권을 자동 선택하여
`SELECT_PIECE` 단계로 진행하고, 둘 이상이면 Player가 이동권을 선택한다.

### 7.1. 빽도

`BACK_DO`는 판 위의 자신 말 또는 업힌 그룹을 기존 진행 경로를 따라 한 칸 뒤로
이동한다. 갈림길과 중앙에서도 새 경로를 선택하지 않고 해당 말이 실제로 지나온
경로를 역순으로 한 칸 돌아간다. 출발/도착이 겹치는 출발칸은 `OUTER_20`이다.
출발점 다음 칸인 `OUTER_1`에서 빽도로 이동하면 `OUTER_20`으로 이동하고,
`OUTER_20`에서 빽도로 이동하면 실제 진입 경로에 따라 외곽 경로는 `OUTER_19`,
지름길 경로는 `CENTER_9`로 이동한다. 빽도로는 완주하지 않는다.

- `READY`와 `FINISHED` 말은 빽도로 선택할 수 없다.
- 판 위에 이동할 말이 하나도 없으면 해당 빽도 이동권은 소멸한다.
- 뒤로 이동한 칸의 같은 소유자 말과는 업고, 상대 말과는 일반 이동과 같이 잡기를
  적용한다.
- `OUTER_1`에서 `OUTER_20`으로 이동한 경우에도 업기와 잡기를 동일하게 적용한다.
- `OUTER_20`에서 이전 칸으로 이동한 경우에도 도착 칸의 업기와 잡기를 동일하게
  적용한다.
- 빽도 자체는 추가 던지기를 주지 않는다. 잡기가 발생한 경우에만 일반 잡기 규칙에
  따라 추가 던지기를 얻는다.

윷 또는 모가 나오면 추가 던지기 1회를 얻는다. 연속 윷·모에 따른 추가
던지기 횟수 제한은 없다.

## 8. 이동권과 행동 순서

던진 결과는 즉시 이동하지 않고 이동권으로 저장한다. 추가 던지기가 끝난
뒤 현재 Player가 보유 이동권을 하나씩 선택해 사용한다. 이동권마다 서로
다른 말 또는 같은 말을 선택할 수 있다.

기본 순서는 다음과 같다.

``` text
윷 던지기
→ 낙이면 해당 던지기만 무효, 기존 이동권이 있으면 이동하고 없으면 턴 종료
→ 윷/모이면 추가 던지기 반복
→ 이동권 선택
→ 서버가 제공한 이동 가능한 말/그룹 선택
→ 필요한 경우 서버가 제공한 경로 선택
→ 이동 및 업기/잡기/완주 판정
→ 남은 이동권 소비
→ 잡기로 얻은 추가 던지기 처리
→ 턴 종료
```

이동 과정에서 상대 말을 잡으면 추가 던지기 1회를 얻는다. 잡기로 얻은 추가
던지기는 현재 보유 이동권을 모두 소비한 뒤 실행한다. 그 결과가 윷/모이거나
다시 잡기가 발생하면 같은 규칙을 반복한다.

## 9. 윷판과 경로

전통 윷놀이의 외곽 경로와 중앙 지름길을 사용한다. 판은 좌표 기반 규칙이
아니라 서버의 Node/Edge 그래프로 모델링한다.

갈림길에 정확히 도착한 말만 지름길을 선택할 수 있다. 갈림길을 지나가는
말은 기존 경로를 유지한다. 선택 가능한 경로가 둘 이상이면 서버가 후보를
제공하고 현재 Player가 하나를 선택한다. 경로 후보가 하나라면 별도 선택을
요구하지 않는다.

### 9.1. 확정 보드 ID와 경로 (2026-09-15)

외곽은 우측 하단에서 위쪽으로 출발하여 `OUTER_1`부터 `OUTER_20`까지
순서대로 이동한다. `OUTER_5`는 우측 상단, `OUTER_10`은 좌측 상단,
`OUTER_15`는 좌측 하단, `OUTER_20`은 우측 하단 도착점이다.
대기 중인 말은 첫 한 칸에 `OUTER_1`로 진입한다. 출발/도착이 겹치는 출발칸인
`OUTER_20`에 정확히 도착한 말은 아직 `ON_BOARD`이며 여기에서 일반 전진 한 칸을
더 통과해야 완주한다. 빽도는 실제 진입 경로의 이전 칸으로 이동한다.

중앙 대각선은 다음 Node를 사용한다. 각 화살표는 한 칸이다.

``` text
CENTER_SHORTCUT_A:
OUTER_5 → CENTER_1 → CENTER_2 → CENTER_3 → CENTER_4 → CENTER_5 → OUTER_15

CENTER_SHORTCUT_B:
OUTER_10 → CENTER_6 → CENTER_7 → CENTER_3 → CENTER_8 → CENTER_9 → OUTER_20
```

`CENTER_3`은 두 대각선이 만나는 공통 중앙 칸이다. 각 대각선은 모서리 사이를
6등분한다. 같은 좌표의 중앙 칸을 경로별로 별도 말 위치로 취급하지 않는다.

- `OUTER_5`에서 이동을 시작하면 `OUTER` 또는 `CENTER_SHORTCUT_A`를 선택한다.
- `OUTER_10`에서 이동을 시작하면 `OUTER` 또는 `CENTER_SHORTCUT_B`를 선택한다.
- A 경로로 `CENTER_3`에 정확히 도착한 뒤 다음 이동에서는 기존 A 경로 또는
  `CENTER_SHORTCUT_HOME`을 선택할 수 있다. HOME은 `CENTER_8 → CENTER_9 → OUTER_20`으로 간다.
- B/HOME 경로의 중앙 이후는 그대로 `CENTER_8 → CENTER_9 → OUTER_20`이다.
- 이동 도중 갈림길을 통과할 때는 선택하지 않고 기존 경로를 계속 진행한다.
- 대각선에서 외곽으로 합류하면 외곽 순서로 계속 이동한다.
- 중앙에서 서로 다른 경로로 온 같은 소유자 그룹이 업히면 이동해 도착한
  그룹의 경로를 새 그룹에 적용한다. 다음 이동의 후보는 서버가 제공한다.

이 ID 목록은 서버 규칙과 Client 표시 좌표를 연결하는 계약이다. Client는
확정된 시작/도착 Node 사이의 짧은 이동만 연출하며 이 그래프로 실제 행동
후보나 도착점을 계산하지 않는다. `READY`/`FINISHED`의 `nodeId`는 `null`이다.

## 10. 업기

이동한 말이 같은 소유자의 말과 같은 위치에 도착하면 업힌다.

- 개인전: 같은 Player의 말끼리 업는다.
- 팀전: 같은 팀의 말끼리 업는다.

업힌 말은 하나의 그룹으로 함께 이동한다. 그룹이 완주하면 포함된 모든 말이
동시에 완주한다.

## 11. 잡기

이동한 말 또는 그룹이 상대 말이 있는 위치에 정확히 도착하면 상대 말을
잡는다. 상대 그룹에 포함된 모든 말은 `READY`로 돌아간다. 잡기를 수행한
현재 Player는 그룹 크기와 관계없이 추가 던지기 1회를 얻는다.

업기, 잡기, 양측 그룹 처리 순서와 최종 말 상태는 서버가 원자적으로
판정한다.

## 12. 완주와 종료

말이 해당 경로의 도착점을 통과하면 `FINISHED`가 된다. 완주에 필요한 이동
수와 통과 가능 여부는 서버가 판정하며 완주한 말은 다시 선택할 수 없다.

- 개인전: 한 Player의 말 4개가 모두 `FINISHED`이면 완주 순서대로 해당
  Player의 순위를 확정한다. 남은 이동권과 추가 던지기는 소멸하고 이후 턴에서
  제외한다. 순위가 확정되지 않은 Player가 한 명만 남으면 해당 Player를
  마지막 순위로 자동 확정하고 GameSession을 즉시 종료한다. 마지막 Player는
  말 4개를 직접 완주할 필요가 없다.
- 팀전: 한 팀의 공유 말 4개가 모두 `FINISHED`이면 해당 팀이 승리한다.

팀전은 승리 조건 충족 즉시, 개인전은 마지막 한 명의 순위가 자동 확정되는 즉시
GameSession을 `FINISHED`로 변경한다. 개인전 순위는 서버가 확정하며
Frontend가 완주 말 수를 바탕으로 계산하지 않는다.

## 13. 실시간 공개 정보

모든 참가자에게 다음 정보를 공개하고 동기화한다.

- 윷판과 모든 말의 위치·상태·그룹
- 현재 턴 Player와 턴 phase
- 확정된 윷 결과와 보유 이동권
- 가장 최근 던지기 결과와 순번(낙 결과 포함)
- 말 이동, 업기, 잡기, 완주
- 잡기와 윷/모로 발생한 추가 던지기 수
- 팀 모드의 팀 구성
- 개인전에서 현재까지 확정된 순위와 본인의 관전 상태
- 개인전 최종 전체 순위 또는 팀전 최종 승리 팀

서버가 현재 Player에게 허용한 행동과 후보만 해당 Player의 개인화된
`/state`에 제공한다. Frontend는 전체 상태로 이동 후보나 경로 후보를 다시
계산하지 않는다.

## 14. 연결 종료와 상태 복구

연결 종료만으로 턴을 넘기거나 Player를 게임에서 제거하지 않는다. V1의 턴
제한 시간, 자동 이동, 장기 미접속 제외 정책은 정의하지 않는다.

새로고침 또는 재접속 시 서버 상태로 다음을 복구한다.

- 게임 모드와 팀 구성
- 윷판, 말 위치와 그룹
- 현재 턴과 턴 phase
- 확정된 윷 결과와 남은 이동권
- 추가 던지기 수
- 현재 Player에게 허용된 행동, 말 후보, 경로 후보
- 완주 현황, 확정된 개인전 순위, 본인의 관전 상태와 종료 결과

과거 WebSocket 이벤트 재생이나 Client 메모리에 의존하지 않는다.

## 15. 게임 종료 화면

개인전은 1위부터 꼴등까지 전체 순위표를 표시한다. 팀전은 승리 팀과 해당 팀
Player를 표시한다. 공통 Room 정책에 따라 방장에게 같은 게임 다시하기와
다른 게임 선택 행동을 제공한다.

## 16. V1 제외 범위

- 1인 및 5인 이상 개인전
- 3:3 이상 팀전
- 기타 지역별 규칙
- 아이템, 캐릭터 능력, 특수 말
- 사용자 지정 규칙
- AI Player
- 턴 제한 시간과 자동 행동

## 17. 서버 권한 요약

서버는 게임 모드와 시작 조건, 팀 정원과 변경, 턴 순서, 낙 확률, 윷가락과 윷 결과,
이동권, 이동 가능한 말과 경로, 말 위치, 업기, 잡기, 추가 던지기, 완주,
개인전 순위와 팀전 승자를 검증하고 확정한다.

Frontend는 다음 의도만 전달한다.

``` text
SELECT_TEAM
THROW_YUT
SELECT_MOVE_TOKEN
SELECT_PIECE
SELECT_PATH
```

**현재 Player가 지금 해야 할 행동만 보여주며, 게임 진행의 진실은 서버
상태다.**
